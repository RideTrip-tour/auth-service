# Регистрация и верификация

Этот документ описывает двухшаговый сценарий регистрации пользователя.

## Сценарий

1. Клиент отправляет `POST /api/auth/register` с `email` и `password`.
2. Сервис валидирует данные, но не создаёт пользователя сразу.
3. Вместо этого генерируется JWT для подтверждения и отправляется письмо на email пользователя.
4. Пользователь переходит по ссылке из письма.
5. Клиент отправляет токен на `POST /api/auth/verify`.
6. Сервис декодирует токен и создаёт пользователя или выполняет смену email, если токен относится к этому сценарию.

## Токен регистрации

Токен формируется в `UserManager.on_before_register`.

В payload используются:

- `email`
- `hashed_password`
- `aud`
- `type=register`

Срок жизни токена - 10 минут.

## Что делает `verify`

Метод `UserManager.verify`:

- декодирует JWT с проверкой secret и audience;
- читает `type` из payload;
- если `type == register`, создаёт пользователя в БД;
- если `type == change_email`, запускает смену email;
- иначе считает токен невалидным.

## Поведение при ошибках

- невалидный, просроченный или токен с неверной audience возвращает `VERIFY_USER_BAD_TOKEN`;
- попытка подтвердить уже существующий email возвращает `VERIFY_USER_ALREADY_VERIFIED`.

## Формат ссылки

Ссылка на подтверждение строится через query-параметр `verify_token`.

Пример:

```text
{origin}/{lk_path}?verify_token=<jwt>
```
